## Backend (`application`)
- Python 3.13, arm64, one container image per function. `functions/<name>/{app.py, requirements.txt, Dockerfile}`; module docstring lists TRIGGER, PURPOSE, ENV_VARS, AWS RESOURCE ACCESS. Shared code: `from shared import tenant, http, dynamo, responses, ...`.
- Stripe over plain HTTPS (`shared/stripe_client.py`), no SDK.
- Responses: `shared/responses.py` `json_response` / `error_response`, errors `{"error": "<code>"}`. Hand-written validators raise `ValueError` (400); unknown fields rejected; writes use a conditional `version` (409 `changed_retry`); 503 when a dependency is down.
- Tenancy (`docs/MULTI_TENANCY.md`, `shared/tenant.py`): `tenant.for_jwt(event, location_id, feature, owner_only)` for admin, `tenant.for_public(location_id, feature)` for guests; foreign ids answer 404. Features: reservations, ordering, catering, terminal, marketing.
- Auth: HTTP API JWT authorizer `cognito` (roles `owner_user`/`staff_user`), `platform` authorizer for operator routes, public routes `NONE`. Guest links are HMAC tokens in `X-Order-Token` / `X-Manage-Token` (`shared/manage_link.py`).
- API: HTTP API v2, paths `/locations/{locationId}/...`, some `{proxy+}` routes dispatched in the Lambda. Contract `docs/openapi.yaml`, checked by `tests/test_openapi.py`. Routes listed in `infrastructure/network/api-gateway/ROUTES.md` (generated by `generate_routes.py`).
- Bot protection: no WAF. Stage throttling per route, `shared/request_guard.py` per-IP/phone/e-mail counters, Cloudflare Turnstile (`shared/turnstile.py`).
- Time: location `timezone` (IANA, default Europe/Stockholm) via `zoneinfo` + `tzdata`; store UTC.
- Money: menu `price` in kronor; catering in öre; VAT 6/12/25%, prices include VAT.
- Tests: pytest + xdist + moto, `cd application && python -m pytest -q -n auto`. `tests/tenant_support.py` builds tables and two tenants. Add tests for all business logic.
- CI: push to `dev` runs tests, builds changed images (a change to `shared/` releases all), blue/green release, smoke test.

## Data stores
- DynamoDB per stage (`<env>-<name>` in dev, `<name>` in prod), tenant isolation by key, PK/SK strings, PITR, SSE.
- `location` (`TENANT#<t>`/`LOCATION#<l>`, GSI `byLocationId`) holds settings: `bookingDurationHours`, `gracePeriodHours`, `businessHours`, `specialDays`, `tableRules`, `tableCombinations`, `ordering`, `cateringSettings`.
- `menu` (`LOCATION#<l>`/`MENU#<id>`), `reservation`, `slot-occupancy`, `order`, `catering-requests`, `catering-request-history` (append-only `OFFER#vNNNN`, `AUDIT#`), `catering-discount-tiers`, `consent-log` (append-only), `marketing` (in `infrastructure/marketing/`), `tenant`, `user`, `request-guard`.
- S3 `catering-documents` bucket: Object Lock (prod COMPLIANCE 7 y, dev GOVERNANCE 1 d), versioned, presigned GET only, keys `<tenantId>/offers|signed|invoices/...`.

## Terraform (`infrastructure`)
- Single root `config.tf`, S3 backend via `-backend-config`, `dev.tfvars` / `prod.tfvars`, no workspaces. aws provider ~>6.
- New Lambda + route + role + table touches: `storage/ecr/<name>/`, `security/iam/<name>/`, `compute/lambda/<name>/{main,alias,outputs,variables}.tf`, `storage/dynamodb/<table>/`, `config.tf` (`<name>_ecr`, `_role`, `_fn`, `lambda_releases` map, `api_gateway` args, `tenant_aware_role_names`, `staff_check_role_names`), `outputs.tf` (`ecr_repository_urls`, CI fails without it), `network/api-gateway/{main,variables}.tf` then regenerate `ROUTES.md`.
- Feature-scoped files are preferred where they exist (`privacy-*.tf`, `marketing/`), to keep `config.tf` edits to a few lines.
- EventBridge Scheduler for recurring and one-time jobs (`security/iam/scheduler-invoke-<name>`), DLQs in `storage/sqs/dead-letter` drained by `dlq-replay`, SNS `platform-alerts`, alarms in `monitoring/alerts`, blue/green via CodeDeploy (`orchestration/lambda-releases`).
- SES: `network/ses` (DKIM), `network/platform-domain` (MAIL FROM, SPF, DMARC `p=none`). Marketing configuration set in `marketing/`; transactional mail (`functions/notification`) has no configuration set.
- Locally only `terraform fmt` and `validate` (scratch copy with `init -backend=false`). `plan` and `apply` run only in CI: push infrastructure to dev and follow the run with `gh run watch <id> --exit-status` before pushing application.

## Frontends (`admin-front-end`, `customer-front-end`)
- React 19, Vite 8, TypeScript 6, react-router-dom 7. No data library, no component library, no i18n library: Swedish copy hardcoded. Plain CSS per feature with CSS variables.
- Scripts: `npm run build` (typechecks), `npm run lint` (oxlint), `npm test` (vitest, jsdom, Testing Library).
- Theme: `booqy-theme` + `<html data-theme>` (`src/shared/theme.ts`, `ThemeToggle.tsx`); admin light by default, customer follows the system. Stored keys must be listed in `src/shared/storageRegistry.ts` (cookie pages render from it).
- Date/time: native `<input type="date|time|datetime-local">` only; no picker component.
- Admin: routes in `App.tsx`, nav `NAV_GROUPS` in `src/shared/AdminLayout.tsx` (gated by `feature`, `ownerOnly`); API `src/shared/api.ts` `apiFetch`, writes wrapped in `busyStart`/`busyEnd`; `shared/Loading.tsx`; `MotionScope`; native `<select>` (`shared/select.css`); settings tabs by hash in `features/installningar/InstallningarPage.tsx`; mocks only where `isApiConfigured()` is false.
- Customer: `SiteProvider` (GET `/site-config`), routes gated by `config.tenant.features`, public `shared/api.ts`, Stripe Payment Element in `shared/payment/`, `shared/MarketingConsent.tsx`, `GuestDataNotice.tsx`.
- Use the `impeccable` skill for UI. Check 375, 768 and 1280 px, light and dark.
